# Checkpoint / Dataset 存储评估配方

训练侧存储评估。评估对象是训练框架的 checkpoint 写入、checkpoint 读取与 dataset 读取三条路径，计算部分被旁路。

方法说明见 [`playbook/checkpoint-dataset.md`](../../playbook/checkpoint-dataset.md)。

## 目标

- 测出训练任务在 checkpoint 与 dataset 两条路径上的 IO 特征。
- 在真实存储与传输路径上测，不在合成负载上测。
- 把结论从单机小参数外推到十万卡。

## 输入

| 输入 | 来源 | 必需 |
|---|---|---|
| 模型代码 | `recipes/model-code-collection` 的语料 | 是 |
| 训练框架与版本 | 所用训练框架及版本 | 是 |
| 并行配置 | DP/TP/PP/EP 的度数 | 是 |
| 数据集布局 | 与真实训练一致的目录结构与文件切分 | 是 |
| 存储后端 | 文件系统或对象存储的挂载方式 | 是 |

## 输出

| 产物 | 说明 |
|---|---|
| IO pattern 记录 | 与 `schemas/io-pattern.schema.json` 一致 |
| 对齐报告 | 真实运行与旁路运行的分项对比 |
| scaling 报告 | 逐级不变量对比与偏差归因 |
| 回链 | `recipe.yaml` 的 `latest_run` |

产物全部放对象存储，仓库只保留回链。

## 步骤

### 1. 选型与跑通

选一个最小可用模型（语料里参数量最小的一档），按真实并行配置跑通若干训练步，不旁路。

通过条件：G0，能跑完一次前向、一次反向、一次 `optimizer.step` 与一次 checkpoint 写入。

### 2. 接入旁路

- 模型用 `torch.device("meta")` 构建。
- 前向用 meta 输入执行；反向用占位梯度，保证 `param.grad` 存在且尺寸正确。
- optimizer 换成占位更新，保留 `state_dict()` 的键结构与分片。
- checkpoint 写入、读取、dataset 读取不改。

通过条件：G1，旁路后跑完与步骤 1 相同的流程，保真边界表填完。

### 3. 小规模对齐

同一配置跑两遍：一次真实、一次旁路，观测配置相同。按 `metrics.yaml` 的容差判定分项。

不通过的项按 `playbook/methodology.md` 的归因顺序排查，结论写进本目录的 `notes` 或方法文档的坑表。

通过条件：G2，全部分项在容差内或有条件通过。

### 4. 放大参数规模

固定集群规模与并行策略，把参数量放大一级。检查：

- 每 rank 写入请求大小分布是否保持；
- 每参数字节数是否保持；
- 分片数与每片大小的变化是否符合预期。

通过条件：G3-a。

### 5. 放大集群规模

固定参数量，把集群规模放到万卡，再外推到十万卡。检查：

- 单 rank 请求大小与并发度是否保持；
- 聚合带宽是否出现饱和拐点；
- 元数据操作数是否先于数据字节数饱和；
- 尾延迟是否超线性增长。

通过条件：G3-b，偏差有归因。

### 6. 登记

回链写入 `latest_run`，覆盖度矩阵更新，未解决的偏差进坑表。

通过条件：G4。

## 配置要求

| 项 | 要求 |
|---|---|
| 并行策略 | 至少覆盖 DP 主导、TP 主导、PP 主导、EP 各一组 |
| checkpoint 实现 | 记录实现名与版本；不同实现不混在一份结论里 |
| 写入方式 | 同步与异步分别测，不合并 |
| 数据布局 | 与真实训练一致；样本量可以缩小，文件切分与格式不能改 |
| 预热 | 固定轮数，报告只取稳态窗口 |

## 验收

| 指标 | 目标 |
|---|---|
| 对齐分项 | 全部分项在容差内，或有条件通过且偏差已归因 |
| 每参数字节数 | 计算值与观测值的相对误差 ≤ 2% |
| scaling 一致性 | 每级相邻偏差在容差内，无单调恶化 |
| 覆盖 | 并行策略、集群规模、参数量三个轴上的已覆盖格子数达标 |
| 可复现 | 配置、commit、拓扑、预热、观测全部登记 |

SLO 指标与判定顺序见 [`playbook/storage-performance.md`](../../playbook/storage-performance.md) 的 3.1 节。
