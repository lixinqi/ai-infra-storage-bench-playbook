# KVCache 存储评估配方

推理侧存储评估。评估对象是 kvcache 的分配、写入、读取、复用、驱逐与跨节点搬运，推理计算被旁路。

方法说明见 [`playbook/kvcache.md`](../../playbook/kvcache.md)。

## 目标

- 测出推理服务在 prefill 与 decode 两个阶段的 KV 读写特征。
- 覆盖多种模型结构与多种推理框架。
- 把结论从单机小规模外推到十万卡推理集群。

## 输入

| 输入 | 来源 | 必需 |
|---|---|---|
| 模型代码与配置 | `recipes/model-code-collection` 的语料 | 是 |
| 推理框架 | vllm / sglang / deepinfer 及其版本 | 是 |
| 负载配置 | 到达间隔、输入长度、输出长度、并发数 | 是 |
| 缓存层级配置 | 显存配额、分层缓存开关 | 是 |
| 存储与传输后端 | 本地盘、远端存储、跨节点传输通道 | 是 |

## 输出

| 产物 | 说明 |
|---|---|
| IO pattern 记录 | 与 `schemas/io-pattern.schema.json` 一致，prefill 与 decode 分开 |
| 对齐报告 | 与真实推理的分项对比 |
| 适配矩阵 | 框架 × 模型 × 缓存能力的已适配格子 |
| 回链 | `recipe.yaml` 的 `latest_run` |

## 步骤

### 1. 跑通真实推理

选一个模型与一个框架，用固定负载跑通一次真实推理，记录请求数、输入输出长度分布、每 token 的 KV 写入字节。

通过条件：G0。

### 2. 接入旁路

- 模型用 `torch.device("meta")` 构建。
- attention 替换为占位实现，但**按真实块表与偏移访问 KV**，读路径不能消失。
- FFN、norm、采样替换为占位实现；停止条件保留。
- 调度器、块管理器、前缀缓存、传输层不改。

通过条件：G1，旁路后跑完相同负载，保真边界表填完。

### 3. 小规模对齐

真实与旁路各跑一次，观测配置相同。除通用度量项外额外核对：

- 每 token KV 写入字节：与模型配置算出的值比对，相对误差 ≤ 1%；
- 前缀命中率：两侧一致；
- 读放大倍数：两侧在容差内。

通过条件：G2。

### 4. 换模型

从语料中取样，覆盖不同层数、KV 头数、注意力变体与 MoE 结构。每个样本跑同一套负载。

通过条件：G3-a，每个注意力变体至少有 5 个模型通过。

### 5. 换框架

三个框架各跑通同一套负载，事件序列语义一致。

通过条件：G3-b，三个框架全部通过，缺一不可。

### 6. 放大参数规模

固定框架与集群，放大模型规模。检查每 token KV 字节是否保持、单块大小如何变化、驱逐频率如何变化。

通过条件：G3-c。

### 7. 放大集群规模

固定模型，把集群放大到万卡，再外推到十万卡。检查跨节点流量、对端分布、传输与存储的时间重叠、尾延迟。

通过条件：G3-d。

### 8. 登记

回链写入 `latest_run`，适配矩阵更新，未解决的偏差进坑表。

通过条件：G4。

## 适配要求

| 项 | 要求 |
|---|---|
| 框架版本 | 每个框架记录具体版本，接口以该版本为准 |
| 适配层位置 | 框架外部；通过插件点接入；必须打 patch 时维护最小 patch 清单 |
| 事件语义 | 统一为分配、释放、读、写、传输、驱逐六类 |
| 失败行为 | 适配失败必须显式报错，不允许静默降级为无 IO |
| CI 覆盖 | 每个框架一个 5 分钟内跑完的最小用例 |

## 验收

| 指标 | 目标 |
|---|---|
| 每 token KV 字节 | 计算值与观测值的相对误差 ≤ 1% |
| 对齐分项 | prefill 与 decode 分别判定，全部在容差内或有条件通过 |
| 多模型覆盖 | 每个注意力变体 ≥ 5 个模型 |
| 多框架覆盖 | 三个框架全部通过 |
| scaling 一致性 | 每级相邻偏差在容差内，无单调恶化 |
