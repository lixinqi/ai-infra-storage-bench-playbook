# IO pattern 对齐度

版本 1.0.0。

## 定义

旁路运行与同等规模真实运行的 IO pattern，在选定度量项上的接近程度。用于判定旁路实现是否成立，是阶段门 G2 的门槛。

## 口径

对齐度不是一个数，而是一组分项。分项由配方的 `metrics.yaml` 用 `items` 与 `tolerance` 声明，check 脚本只算声明过的项，逐项判定，全部通过才算对齐。

| 度量项（tolerance 键） | 计算 | 单位 |
|---|---|---|
| `request_size_distribution` | 两组直方图归一化后的 L1 距离；两边的 `bucket_edges` 必须相同 | 距离，0–2 |
| `read_write_ratio_bytes` | 按字节口径的读写比相对误差 | 比例 |
| `read_write_ratio_ops` | 按请求数口径的读写比相对误差 | 比例 |
| `concurrency_p50` / `concurrency_p95` / `concurrency_max` | 并发度分位数的相对误差 | 比例 |
| `sequentiality` | 顺序请求占比的绝对差 | 绝对差 |
| `hotness` | Top-K 块访问占比的绝对差 | 绝对差 |
| `per_token_kv_bytes` | 每 token KV 写入字节的相对误差；需要记录的 `tokens_generated` | 比例 |
| `timing_peak` | 每秒峰值字节数的相对误差；需要记录的 `timing.peak_bytes_per_second` | 比例 |

计算约定：

- 两侧使用相同的时间窗口，窗口从稳态开始，长度相同。
- 窗口起点由预热排除规则确定：丢弃前 N 轮，N 写进配方参数。
- 直方图分桶边界固定，两边不一致时判定为不可比，不给结论。
- 相对误差的分母取真实运行的值。

## 阈值

阈值写在 `recipes/<name>/metrics.yaml` 的 `tolerance` 里，由评审把关。初始参考值：

| 度量项 | 参考阈值 |
|---|---|
| `request_size_distribution` | 0.10 |
| `read_write_ratio_bytes` | 5% |
| `read_write_ratio_ops` | 10% |
| `concurrency_p50` | 10% |
| `concurrency_p95` | 20% |
| `sequentiality` | 0.05 |
| `hotness` | 0.05 |
| `per_token_kv_bytes` | 1% |
| `timing_peak` | 10% |

标定方式：同一配置做 5 次真实运行，取两两最大差异作为容差下限；若该值高于参考值，改用实测值，并注明标定日期与基准运行的回链。

## 采集

| 原始数据 | 来源 | 必需 |
|---|---|---|
| 每次请求的偏移、大小、时间戳、方向 | 应用层 hook | 是 |
| 设备或客户端的请求统计 | 系统层 | 是（记录必须包含 `sys`） |
| 存储侧请求日志 | 存储服务 | 否，有则用于三方核对 |

记录结构见 `schemas/io-pattern.schema.json`。记录必须声明至少两层采集来源且包含 `sys`，否则不能用于对齐判定。

交叉核对：应用层与系统层的总字节数偏差超过 1% 时，对齐度结论作废，先解释偏差。

## 判定

| 情况 | 结论 |
|---|---|
| 全部声明项在阈值内 | 对齐通过 |
| 任一项超出，归因已写清、偏差方向可控 | 有条件通过，需评审确认 |
| 任一项超出，归因不明 | 不通过 |
| 阈值缺失、记录非法、观测失败 | 不可比，重跑 |

## 已知限制

- 只能判定"像不像"，不能判定"对不对"。两侧同时漏采同一类请求时，仍会判为对齐。
- 时序分项对观测开销敏感，开销本身超过 3% 时，时序结论无效。
- 小规模上对齐，不保证放大后仍对齐；放大后的偏差由 scaling 一致性负责。
