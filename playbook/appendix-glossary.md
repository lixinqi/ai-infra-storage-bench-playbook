# 附录 A：基础术语

本附录只解释各篇文档里反复出现、但属于存储与推理领域而非本项目的词。项目自造词（评估集、配方、旁路、保真、回链）在 `README.md` 的「术语」里，不重复。

## A.1 并行策略

| 缩写 | 全称 | 切分对象 |
|---|---|---|
| DP | data parallel，数据并行 | 把 batch 切开，每个 rank 持有完整模型 |
| TP | tensor parallel，张量并行 | 把单层权重按维度切开 |
| PP | pipeline parallel，流水线并行 | 把层分成若干段，按阶段流水 |
| EP | expert parallel，专家并行 | 把 MoE 的专家分到不同 rank |

四种可以组合（例如 DP × TP × PP）。组合方式直接改变 checkpoint 的分片与每 rank 的写入量，因此 scaling 一章把并行策略列为独立维度。

## A.2 模型结构

| 词 | 含义 |
|---|---|
| MoE | mixture of experts，混合专家。每层有多个前馈专家，按路由只激活其中一部分 |
| GQA | grouped-query attention，分组查询注意力。多个查询头共享一组 KV 头，KV 头数少于查询头数 |
| MQA | multi-query attention。所有查询头共享一组 KV 头，是最省 KV 的一种 |
| MLA | multi-head latent attention。把 KV 压缩到低维潜空间再展开，KV 体积小但访问模式特殊 |
| prefill | 预填充。一次处理整个输入序列，KV 按 token 成批写入 |
| decode | 解码。逐 token 生成，每步只写一个 token 的 KV，读历史 KV |

KV 头数、层数与 head_dim 共同决定每 token 的 KV 字节数，这是 kvcache 评估里最容易核对的一项。

## A.3 存储与 IO

| 词 | 含义 |
|---|---|
| 分片（shard） | 把一份大文件或一份状态切成若干片，分别写到不同位置。分片数决定并发度与元数据量 |
| 聚合带宽 | 多个 rank 同时读写时，存储侧承受的总带宽。它不等于单 rank 带宽乘以 rank 数：存储侧饱和后会走平 |
| 元数据操作 | 创建、删除、重命名、stat、列目录这类不搬运数据本体、只改目录信息的操作。小文件多、分片多时，元数据可能先于数据饱和 |
| 读放大 | 实际读取的字节数除以逻辑上需要的字节数。缓存命中率低、块重复读、预取过多都会放大读取 |
| 尾延迟 | 延迟分布的高分位，常用 P95、P99、P999。大规模下它比平均值更能反映排队与重传 |
| 基线 | 上一次通过验收的那次运行的度量值。不是"最近一次运行"，失败的运行不更新基线 |
| 无结论 | 运行没有产生可用度量（超时、观测失败、断言失败）。它既不算通过也不算失败，不计入通过率 |

## A.4 旁路相关

| 词 | 含义 |
|---|---|
| meta device | PyTorch 的一种设备。张量只保留 dtype 与逻辑尺寸，不分配真实存储，因此前向可以执行但不产生计算 |
| module mock | 把指定模块替换成返回约定张量的实现，其余代码路径不变 |
| process group | PyTorch 分布式通信的进程组。mock 它可以在单卡上跑通按 rank 分支的代码，但 rank 之间的真实同步会消失 |
| 激活检查点 | activation checkpointing，训练时用重算换显存。旁路后其时间热点消失，写入时序会变 |
