# 扩展：从缺口到新版本

评估集是静态产物：一个版本的用例清单构建完成之后，不会自己变化。会变化的是 playbook——它发现缺口、生成候选、验证、发布新版本的评估集。

对外常说的"自进化"指的是 playbook 的这套能力，不是评估集自己会动。混淆这两者，会把"数据"和"产生数据的程序"当成同一个东西，后续讨论覆盖、版本、回归时都会失焦。

新模型出现、框架升级、并行策略变化时，覆盖度会随时间下降。本篇要解决的是：**让 playbook 持续产出覆盖不衰减的新版本，并且不让历史结论悄悄失效。**

## 1. 闭环的四个动作

```text
发现缺口 → 生成候选 → 回归验证 → 版本收敛
   ↑                                    │
   └────────────────────────────────────┘
```

| 动作 | 输入 | 输出 | 是否自动 |
|---|---|---|---|
| 发现缺口 | 覆盖度矩阵、失败模式、外部信号 | 缺口清单（带优先级） | 自动 |
| 生成候选 | 缺口清单、模型清单、框架发布信息 | 候选用例（模型 + 配置 + 负载） | 自动生成，人工确认 |
| 回归验证 | 候选用例、现有基线 | 通过 / 不通过 / 无结论 | 自动 |
| 版本收敛 | 回归结论 | 新评估集版本、回链、变更记录 | 人工确认 |

## 2. 触发条件

| 触发 | 信号来源 | 响应 |
|---|---|---|
| 新模型发布 | 模型清单定期扫描、发布公告 | 加入候选池，跑可跑性验证，按覆盖度决定是否入集 |
| 框架新版本 | 框架发布源、镜像更新 | 适配层回归，失败则标记适配过期 |
| 覆盖度下降 | 覆盖度矩阵的空白格子增多 | 生成针对空白格子的候选 |
| 失败模式变化 | 评估服务里新增的失败分类 | 新增用例复现该失败 |
| 新并行策略 | 训练或推理配置变更 | 新增并行组合的用例 |
| 存储后端变更 | 基础设施变更通知 | 重跑受影响后端的对齐用例 |
| 历史结论被推翻 | 回归时与基线不一致 | 冻结相关结论，进入人工排查 |

触发信号要写进服务配置，不允许靠人记得去跑。

## 3. 覆盖度矩阵

矩阵的轴由各配方的 `metrics.yaml` 定义，但必须包含"模型结构"与"系统规模"两个轴：

| 轴 | 取值 |
|---|---|
| `arch_family` | 按 `playbook/model-code-collection.md` 的架构族划分 |
| `model_scale` | 参数量分桶，至少 6 个量级 |
| `attention` | MHA / GQA / MQA / MLA / 线性注意力 / 滑动窗口 |
| `framework` | vllm / sglang / deepinfer（仅 kvcache） |
| `parallel` | DP / TP / PP / EP 的代表组合 |
| `cluster` | S0–S5 |
| `io_feature` | 小请求密集 / 大块顺序 / 高并发 / 热点访问 / 突发 |

矩阵的每个格子记录：用例数、最近一次通过时间、最近一次失败。空格子分两种：

- **应该有但没有**：登记为缺口，进候选生成。
- **明确不需要**：登记为豁免，写理由与复核日期。

豁免不是垃圾桶。豁免必须定期复核，否则会变成永久空白。

## 4. 缺口分析与候选生成

### 4.1 缺口打分

```
优先级 = 覆盖权重 × 结构新颖度 × 规模重要性 / 预计成本
```

| 因子 | 取值方式 |
|---|---|
| 覆盖权重 | 该格子在下游使用中被引用的次数 |
| 结构新颖度 | 与现有样本的最小结构距离，越大越新 |
| 规模重要性 | 目标规模与该格子规模的差距 |
| 预计成本 | 由配方声明的单次运行成本估算 |

分数只用于排序，不用于自动决定入集。入集决策留给人。

### 4.2 候选来源

| 来源 | 生成方式 |
|---|---|
| 模型清单的新增项 | 按结构距离挑选，避免与现有样本重复 |
| 架构族缺口 | 从公开模型里找该族的最新与最大样本 |
| 框架能力缺口 | 框架新版本引入的缓存/传输能力，构造对应用例 |
| 失败复现 | 从失败分类里取代表性样本，构造成最小复现用例 |
| 负载缺口 | 用现有模型搭配未覆盖的负载模式 |

候选用例必须带完整运行规格，能直接提交给评估服务。生成出来但不能跑的候选，不算候选。

## 5. 回归

### 5.1 基线

基线不是"上一次的结果"，而是**上次通过版本的结果**。判定规则：

| 情况 | 结论 |
|---|---|
| 度量在容差内 | 通过 |
| 度量超出容差，但运行规格有变化 | 不可比，需要重跑同规格 |
| 度量超出容差，规格相同 | 不通过，进入排查 |
| 运行失败 | 无结论，不计入通过率 |

### 5.2 回归范围

| 层级 | 范围 | 频率 |
|---|---|---|
| 冒烟 | 每个配方的 S0 最小用例 | 每次提交 |
| 常规 | 全部 S0 + 抽样 S1 | 每日 |
| 全量 | 全部用例 | 每周或发布前 |

### 5.3 回归结果的处理

- 通过：更新基线与覆盖矩阵的"最近一次通过时间"。
- 不通过：冻结相关结论，生成排查任务，不自动改配方。
- 无结论：保留原基线，不覆盖；连续三次无结论的用例标记为不稳定，退出回归集并进入修复队列。

## 6. 版本收敛

评估集版本由三部分组成：

```
<配方版本>+<用例集版本>.<指标版本>
```

| 部分 | 变化条件 |
|---|---|
| 配方版本 | 流程、旁路方式、验收标准变化 |
| 用例集版本 | 增删用例、调整负载配置 |
| 指标版本 | 度量定义变化 |

服务在运行时校验三者兼容。评估集版本变更必须写进 `CHANGELOG.md`，并注明影响的历史结论范围。

## 7. 人工介入边界

| 动作 | 自动 | 人工 |
|---|---|---|
| 扫描新模型、计算结构距离 | 是 | — |
| 生成候选用例 | 是 | — |
| 候选入集 | 否 | 是 |
| 跑冒烟与回归 | 是 | — |
| 更新基线与覆盖矩阵 | 是 | — |
| 修改指标口径 | 否 | 是 |
| 修改阈值 | 否 | 是 |
| 判定结论失效 | 否 | 是 |
| 更新评估集版本 | 否 | 是 |

**自动化的边界是：可以自动产生数据与候选，不能自动改变语义。** 口径与阈值是语义；用例是数据。混淆这两者，就会出现"评估集追着实现改，越改越宽松"。

## 8. 扩展机制的指标

| 指标 | 定义 | 用途 |
|---|---|---|
| 缺口发现速度 | 新信号出现到进入缺口清单的时长 | 闭环灵敏度 |
| 缺口收敛速度 | 缺口登记到补齐的时长 | 闭环效率 |
| 覆盖增长率 | 已覆盖格子数的时间导数 | 覆盖是否在扩大 |
| 回归通过率 | 通过 / 有结论 | 稳定性 |
| 无结论率 | 无结论 / 全部 | 运行质量 |
| 过时配方比例 | 超过一个版本周期未回归的配方占比 | 维护健康度 |
| 豁免复核及时率 | 按时复核的豁免数 / 全部豁免数 | 空白是否失控 |

这些指标的定义在 `meta-evaluation/playbook-metrics.yaml`，本文件只引用。

## 9. 反模式

| 反模式 | 表现 | 后果 |
|---|---|---|
| 只加不减 | 用例数只增不减，运行时长持续上升 | 回归逐渐没人跑，闭环停转 |
| 追着实现改口径 | 结果不好看就调阈值 | 评估集失去约束力 |
| 自动改语义 | 让自动流程直接改配方与阈值 | 无法追溯结论变更 |
| 用平均值代替分布 | 只报平均带宽 | 掩盖尾延迟与突发 |
| 基线取最近一次 | 用失败的结果当基线 | 指标持续下滑而不报警 |
| 缺口永不补齐 | 空白格子长期挂账 | 覆盖度名存实亡 |

## 10. 开放问题

- 结构新颖度与成本的权重如何标定，目前是经验值。
- 用例集只增不减的清理策略：哪些用例可以退役，退役后历史结论怎么处理，尚未定规则。
- 框架升级导致的大面积适配失败，是否需要独立的"适配版本"概念。
- 自动生成的候选如何避免与已有用例等价但看起来不同的重复。
