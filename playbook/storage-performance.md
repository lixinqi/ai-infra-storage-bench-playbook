# 存储表现：一个样本怎么判

## 1. 这篇补的是哪一段

评估分两件事，之前只写了前一半：

| 问题 | 产出 | 定义在哪 |
|---|---|---|
| 这个样本向存储提出了什么要求 | IO pattern：请求大小、读写比、并发、时序 | [`methodology.md`](methodology.md) 的「IO pattern 的度量项」 |
| 存储在这个要求下给得怎么样 | 存储表现：吞吐、延迟、饱和度、公平性、错误 | 本篇 |

一个**样本**是一次运行的最小单位：某个模型 + 配置 + 负载 + 拓扑，配方的 `recipe.yaml` 定义了它。样本跑完，除了 IO pattern，还要产出存储表现，才能下"存储行不行"的结论。

## 2. 测什么

| 指标 | 定义 | 采集点 | 单位 |
|---|---|---|---|
| 吞吐 | 稳态窗口内完成的字节数 / 窗口时长；读、写、总分开 | 存储侧优先，系统层兜底 | B/s |
| IOPS | 完成的请求数 / 窗口时长；按请求大小分桶 | 存储侧 | 次/s |
| 延迟 | 单个请求从发起到完成的时长；P50 / P95 / P99 / P999，读、写、元数据分开 | 客户端计时，存储侧交叉核对 | ms |
| 排队深度 | 同一时刻未完成的请求数分布 | 系统层 | 个 |
| 饱和度 | 设备利用率；聚合吞吐随并发增长是否已走平 | 存储侧 | 百分比 |
| 公平性 | rank 间吞吐的最大/最小比、Gini 系数 | 存储侧按 rank 拆分 | 比值 |
| 错误 | 超时率、重试率、错误码分布 | 客户端与存储侧 | 次/s、比例 |
| 元数据 | 创建、stat、列目录的 op rate 与 P99 | 存储侧 | 次/s、ms |
| 稳定性 | 稳态窗口内每秒吞吐的变异系数 | 存储侧 | 百分比 |
| 效率 | 实测聚合吞吐 / 上限；上限取链路、后端、客户端三者的最小值 | 计算 | 百分比 |

三条约定：

- **分布优先。** 报告吞吐用中位数与区间，报告延迟用分位数；只报平均值会把尾延迟藏起来。
- **按 rank 归一。** 跨规模比较时用"每 rank 吞吐""每参数字节每秒"，否则规模一变就没法比。
- **元数据单独报。** 分片多、小文件多时，元数据操作会先于数据字节饱和，混在总 IOPS 里看不出来。

## 3. 怎么采

三层，至少两层，优先"存储侧 + 系统层"：

| 层 | 能拿到 | 局限 |
|---|---|---|
| 应用层 | 请求的逻辑含义、发起时间 | 看不到合并、排队与重试 |
| 系统层 | 真实下发、队列深度、重传 | 丢失逻辑归属 |
| 存储侧 | 服务端吞吐、延迟、错误、按 rank 拆分 | 采样率与聚合粒度受限 |

采集规则：

1. **预热。** 丢弃前 10% 的窗口或前 N 轮，取稳态。预热规则写进配方。
2. **窗口长度。** 至少 60 秒或至少固定字节数，取较长者。
3. **稳态判定。** 窗口内每秒吞吐的变异系数 > 10% 时，延长窗口；仍不达标则标记"不稳"，不出结论。
4. **重复。** 同一配置至少 3 次；报告 min / median / max。3 次的中位数极差超过 10% 视为不可比。
5. **独占。** 同一存储后端同一时刻只跑一个高带宽样本，否则测的是争用，不是表现。
6. **观测开销。** 开关观测各跑一次，关键指标变化 ≤ 3%；超过则降采样或改用系统层。

## 4. 怎么判

判定必须在运行前声明模式与阈值，写进配方的 `recipe.yaml`（当前用 `notes` 字段承载，schema 后续加字段）。三种模式：

| 模式 | 比较对象 | 阈值来源 | 适用 |
|---|---|---|---|
| `sla` | 绝对要求 | 需求文档或服务等级 | 有明确指标下限的场景 |
| `baseline` | 上一个通过验收的版本 | 噪声带宽（默认 5%） | 回归、版本对比 |
| `efficiency` | 理论上限 | 效率百分比下限（初始 60%，待标定） | 判断还有多少余量 |

判定表：

| 情况 | 结论 |
|---|---|
| 全部声明指标达到阈值 | 通过 |
| 任一指标未达阈值，归因清楚且不影响目标结论 | 有条件通过，需评审 |
| 任一指标未达阈值，归因不明 | 不通过 |
| 窗口不稳、重复不足、观测开销超限、配置变化 | 不可比，重跑 |
| 存储侧与客户端数据偏差 > 5% | 不可比，先解释偏差 |

**判定模式与阈值不允许在结果出来后调整。** 觉得阈值不合理，改配方、走评审、重跑；不要改结论。

## 5. 一个样本的报告

`performance.json`，与 `metrics.json` 并列存放：

| 字段 | 内容 |
|---|---|
| `run_id` | 对应的运行 |
| `verdict_mode` | `sla` / `baseline` / `efficiency` |
| `window` | 预热长度、稳态起止、窗口内变异系数 |
| `throughput` | 读、写、总的字节每秒；每 rank 值 |
| `iops` | 总请求每秒；按大小分桶 |
| `latency` | 读、写、元数据的 P50 / P95 / P99 / P999 |
| `saturation` | 利用率、队列深度、是否已饱和 |
| `fairness` | rank 间 max/min、Gini |
| `errors` | 超时、重试、错误率 |
| `metadata` | op rate、P99 |
| `efficiency` | 实测、上限、效率 |
| `verdict` | `pass` / `fail` / `inconclusive` |
| `evidence` | manifest、io-pattern、原始数据的位置与 sha256 |

报告只引用，不入库；回链写进配方的 `latest_run`。

## 6. 常见错误

| 错误 | 后果 | 处置 |
|---|---|---|
| 只报平均吞吐 | 尾延迟被掩盖，结论在真实负载下失效 | 分布优先 |
| 窗口包含预热 | 吞吐虚高或虚低 | 固定预热规则 |
| 与其它样本并行跑 | 测到的是争用 | 同后端串行 |
| 跨后端直接比较 | 后端上限不同，结论无意义 | 只在同一后端内比较，或用效率模式 |
| 单次运行当结论 | 噪声被当成信号 | 至少 3 次，报告离散度 |
| 事后调整阈值 | 结论不可比 | 运行前声明，改动走评审 |

## 7. 与其它文档的关系

- IO pattern 定义在 [`methodology.md`](methodology.md)，本篇消费它的输出。
- 放大到多级规模时，存储表现随规模的变化由 [`scaling.md`](scaling.md) 的规则处理；本篇只管单级。
- 判定阈值属于配方，写在 `recipes/<name>/` 下，与本篇的口径一致。
