# 评估 playbook 自身的方法

## 1. 什么算"有效"

一句话：**给定一次存储侧的改动，playbook 能产出可复现、可外推、能改变决策的结论。**

三个词各有一个可检验的含义：

| 词 | 检验方式 | 反例 |
|---|---|---|
| 可复现 | 没参与编写的人照着配方独立跑，结论一致 | 只有原作者能跑通 |
| 可外推 | 小规模结论按 [`scaling.md`](../playbook/scaling.md) 放大后，与实测不矛盾 | 单机结论在集群上被推翻 |
| 能改变决策 | 结论被用于取舍、排期或回滚 | 报告写完没人看 |

有效性不是"文档写完了"，也不是"跑了多少次"。下面五个问题各自有测量方法。

## 2. 五个问题与测法

### 2.1 可执行性：别人能不能跑通

盲复现实验：

- 每季度抽 3 个配方，交给没参与编写的人。
- 只给配方目录与运行请求，不给口头说明。
- 记录：跑到 G0 的耗时、卡点位置、是否成功、是否需要问人。
- 判定：一次通过率 ≥ 80%；每个卡点必须能对应到文档的某一节，否则记文档缺口。

### 2.2 结论可靠性：结论会不会被推翻

结论追踪：

- 每个对外结论登记一条：结论、配方版本、指标版本、证据回链。
- 后续运行或生产事件出来后，标记"站住 / 被推翻 / 无法判定"。
- 判定：翻案率 ≤ 10%；被推翻的结论必须归因到"评估方法错"还是"环境变化"。

翻案率只统计有后续验证的结论，不把"没人验证"算成站住。

### 2.3 覆盖增长：bench 是不是在变强

覆盖度时间序列：

- 每月对 [`coverage.md`](../metrics/coverage.md) 定义的矩阵拍一次快照。
- 计算覆盖度、缺口数、缺口登记到补齐的中位时长。
- 判定：覆盖度不下降；缺口收敛中位数 ≤ 30 天；豁免数量不增长。

### 2.4 成本：跑一次要多少

成本核算：

- 每次运行记录卡时、存储读写量、人力小时。
- 按配方与规模档位聚合，得到单位成本（每样本、每档位）。
- 判定：不设绝对目标，看趋势；成本上升超过 20% 且覆盖度没涨，需要解释。

### 2.5 决策价值：有没有人用

使用追踪 + 访谈：

- 登记结论被引用的情况：设计评审、排期、回滚、采购。
- 每季度做 5 人以上的半结构化访谈，问三件事：哪条结论改变了决定、哪条结论不敢用、缺什么。
- 判定：至少 2 条结论在季度内改变了决定；"不敢用"的原因要能归到方法缺口或证据不足。

## 3. 对照实验

要判断"playbook 本身有没有用"，最直接的是对照：

| 实验 | 做法 | 看什么 |
|---|---|---|
| 有 / 无 | 同一存储改动，一组用 playbook 结论，一组凭经验 | 决策差异与后续返工 |
| 新旧配方 | 同一批样本，两版配方各跑一次 | 结论一致率与成本差 |
| 阈值敏感度 | 同一结论，阈值上下浮动 10% | 结论是否翻转（翻转说明样本不足） |

对照实验每半年做一次，样本量不足时只记录，不下结论。

## 4. 判定与行动

| 指标 | 目标 | 连续两季未达标时 |
|---|---|---|
| 盲复现一次通过率 | ≥ 80% | 定位卡点，改文档或改配方 |
| 翻案率 | ≤ 10% | 检查评估方法与不变量 |
| 覆盖度 | 不下降 | 补缺口，走 `extension.md` 的流程 |
| 缺口收敛中位时长 | ≤ 30 天 | 调整优先级 |
| 改变决策的结论数 | ≥ 2 / 季 | 检查结论是否可读、是否够具体 |

未达标不自动触发改规则；先写一条 `decisions/` 记录，说明是方法问题、资源问题还是样本不足。

## 5. 结果去哪

1. 数据存对象存储，仓库里只留回链。
2. 季度评审写进 `decisions/`：结论、证据、要改的文档或配方。
3. 改动按 [`CONTRIBUTING.md`](../CONTRIBUTING.md) 走评审。
4. 下一季度重新测，比较趋势。

闭环是：测自己 → 找到方法缺口 → 改 playbook → 再测自己。评估集的扩展由 [`extension.md`](../playbook/extension.md) 定义，两者不要混：一个改评估集的覆盖，一个改产生评估集的方法。

## 6. 反模式

| 反模式 | 表现 | 后果 |
|---|---|---|
| 只统计使用量 | 跑了多少次、用了多少人 | 用得多的可能是最不可靠的配方 |
| 只发问卷不做访谈 | 平均分很好看 | 具体问题被平均数抹平 |
| 自己人复现 | 原作者跑通就算通过 | 盲复现失去意义 |
| 把"文档写完"当成功 | 里程碑是文档数量 | 没人照着跑 |
| 翻案率不归因 | 只知道结论错了 | 不知道改哪里 |

## 7. 最小启动

第一版没有历史基线，先只测三件事：

1. 盲复现一次通过率（3 个配方）。
2. 翻案率（从第一条登记结论开始）。
3. 缺口收敛中位时长（从 `extension.md` 的缺口清单开始）。

满一个季度后，用实测值定目标，再补齐成本与决策价值两项。
