# 评估手册自身

这里评估的不是存储，而是**这套手册好不好用**。手册是给人执行的东西，用不上就是废纸。

## 评什么

| 维度 | 问题 | 指标 |
|---|---|---|
| 可执行性 | 别人照着一份配方能不能跑通 | 配方执行成功率 |
| 复用 | 新评估集有没有复用已有配方，复用了多少 | 配方复用率 |
| 结论可靠 | 配方给出的结论有没有被后续运行推翻 | 结论翻案率 |
| 维护成本 | 维持评估集需要多少人力与机时 | 单次运行成本、维护人时 |
| 缺口收敛 | 发现的缺口多久能补上 | 缺口收敛时长 |

## 怎么用

1. 每季度按 [`survey-template.md`](survey-template.md) 收集一次配方使用者的反馈。
2. 每季度统计一次 [`playbook-metrics.yaml`](playbook-metrics.yaml) 里的指标。
3. 指标连续两个季度恶化时，在 `decisions/` 写一条记录，说明是手册的问题还是资源的问题。

## 边界

- 这里只放**指标定义与模板**，不放问卷原始数据、不放大规模统计结果。
- 统计结果放对象存储，仓库里写回链。
- 评审结论不写进这里，写进 `decisions/`。

## 反模式

- 用"文档写完了"当成功标准。文档写完只是开始，跑通才算。
- 只统计使用量不统计翻案率。用得多的配方可能是最不可靠的那个。
- 拿调查问卷的平均分当结论，不看具体哪一条说了什么。
